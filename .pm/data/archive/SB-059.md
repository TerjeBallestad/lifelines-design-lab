      ## What a case picker needs

      1. Discovery — replace both static `?raw` imports with one shared module using `import.meta.glob('/content/cases/**/*.case.md', { query: '?raw', import: 'default', eager: true })`. Verified against the installed vite 8.0.14 (`as:` is deprecated there, `query` + `import` is current). Eager keeps the case files inside the module graph, so the existing external-edit reload behavior survives. A `fetch()` loader would lose it.
      2. Identity carrier — a `?case=<path>` URL param on both lens pages, defaulting to the single case. It survives reload, it rides the existing cross-links with one href change each, and it is the natural localStorage key.
      3. One `activeCase` module owning the path, the text, and the four key builders (`draftKey(path)`, `posKey(path)`, `modeKey(path)`, `pinKey(path)`). This also kills the duplicated DRAFT_KEY literal.
      4. Save takes a target — POST `/__save-case?path=<relpath>`; the plugin resolves it, rejects anything outside `content/cases/` or not ending in `.case.md`, and keeps `lastSaved` in a per-path Map so the reload suppression stays correct per file.
      5. Picker UI — the file-name span becomes a select over the glob keys, labelled with the compiled `slice.title`.

      Not needed: a case manifest file, a compiler change, a change to the generator scripts, or anything from the generated module. The Playtest lens can be case-agnostic with changes in 6 files, all in the shell.

      ## Cost note
      Only one case exists on disk (`content/cases/olsen/`), so a picker is untestable as a picker until a second case exists. The plumbing is still worth doing at the point the lens is built — a second `.case.md`, even a 10-line stub, makes it verifiable.

## Question
Inventory every place the toolchain hard-wires the olsen case, and state what a case picker needs. Known so far: the vite caseSave() plugin POSTs to a fixed path content/cases/olsen/tiny-olsen.case.md, gen:olsen scripts, the generated src/content/blueprint/generated/tinyOlsen.ts module, and the prototype pages' load paths.

## Why it blocks
The map's ruling is case-agnostic from day one. The content display cannot claim that until the loading seam is known.
