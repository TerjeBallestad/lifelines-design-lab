SB-051 closing verdict (Terje): pin mode wins the layout question, but 'it is still quite hard to manage all the content' — the strain is the node count on screen, not the scatter. The layout engine is settled; scoping is the open feel question.

The playable question: which scoping tool makes a 90-node case navigable while writing — (a) neighborhood focus: select a node, the board shows only N hops around it; (b) kind/lane filters: toggle whole families (weave, clocks, tiltak) off; (c) grouping frames (SB-038: comment boxes carry 80+ node overviews); (d) fuzzy jump-to-node as the primary navigation, board as context? Probably a combination — the probe should let each be toggled independently on the real Olsen case.

Least build: filter/focus at render time over the existing graph — no markup changes, no layout changes (pin mode from SB-051 stays as-is underneath).

Why it blocks: this is the remaining half of the SB-048 'canvas presentation fails' finding — SB-051 answered layout, this answers volume. Feeds SB-045 (the arrival-check probe should run after the board is manageable).
