      ## 2. Runtime concepts 0.2 lacks syntax for

      - **Pacing:** 0.55s/0.85s burst timing (phone_panel.gd:56-57, 478-483), burst reset on player rows, generation-guarded reveal. No syntax for beat timing.
      - **Card-keying — the actual choice model:** a choice is a Funn card the player drops. exchanges keyed by card_id (contact_call.gd:49); chat threads keyed by needs == [exactly one fact] (case_engine.gd:742-746). Round 3 REMOVED ask buttons ("the HAND is the player's half of the conversation"). 0.2 cannot say which card opens a branch.
      - **Soft-reject:** per-call + per-pack generic deflection with reason codes no_recipe/already_set/not_eligible (case_engine.gd:1022-1035).
      - **Pair crafting:** two cards, unordered match, both gates pass → Frank's lines, question revealed, cards FOLD OUT of the Hand, a reading lands (case_recipe.gd, case_engine.gd:1020-1071). Arity-2 input + irreversible card consumption — no 0.2 concept.
      - **Row registers:** question/answer/bark/proposal/teaser/card/reading/tanke, each renders differently (frank_chat.gd:13-31).
      - **Speaker tagging:** call lines carry `who` (du vs contact).
      - **Liftable spans:** a fact inside a call line is a tappable [url=fact:] span — no 0.2 syntax marks a span within a line.
      - **Three lifetimes of "used up":** follow-ups per-case persisted; _call_asked UI-session, cleared on hang-up; last_entry_id deliberately not serialized. `*` is one sigil for three lifetimes.
      - **Computed picks:** ask_frank_advice scores proposals by overlap + threshold + authored tiebreak (case_engine.gd:833-855).
      - **Gate doubling as world liveness:** the call gate also decides contact reachability on the rail, plus a sim override (Grete's line dies with her).
      - **Hjemmebesøk is not content at all:** social_visit_director.gd:100-150 hardcodes the visit beats in GDScript — no pack representation exists for weave to compile into.

      ## 3. Verdict — the emit boundary

      Wider than "emit with warnings", for an upstream reason: **markup 0.1 does not emit the conversation layer at all.** The generator stops at day beats; frank_chat/frank_proposals/recipes/calls/pair lines exist only as hand-edits — docs/case-content-runtime.md:11 says in writing "Edit it directly, leave the .case.md alone, and never run the generator." 0.2 is the FIRST markup to claim this territory.

      A shallow subset maps mechanically: weave depth ≤ 1 (`*` at depth 1, `+` at depth 0, reply lines, `~ pay`) → frank_chat shape; call blocks → calls shape. But hubs, diverts, END, deep nesting, sequence text, asked-counts, and every `~` except pay have NO target field to degrade into — warnings would drop authorial intent, not preserve it.

      Two deep mismatches:
      1. **The choice model is inverted.** 0.2: a choice is a text line the player selects. Runtime: a choice is a card the player drops (card_id required + unique per call, case_pack_validator.gd:69-77). Free-text `*` choices under a call compile to exchanges the UI cannot surface — there is no menu. 0.2 needs a first-class "keyed by card X" notation. Spec change, not a warning.
      2. **§6 grammar is partly DISJOINT from PredicateSpec, not a superset.** Six new terms need engine ops; meanwhile §6 drops hypothesis_chosen and slot_filled, which content already uses.

      Practical read: aim 0.2 v1 at the chat/follow-up shape plus card-keyed call exchanges (honest mapping, real payoff); defer hubs/diverts/END/deep nesting rather than warn; land missing predicate ops as parallel engine work; expect pacing, row registers, liftable spans and fold-out-on-craft to need invented syntax — those are the parts players actually feel.
