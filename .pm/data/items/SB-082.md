## Task
Cut the seam SB-060 found. Move the surface renderers out of the canvas probe into a shared module that the canvas rail, the script lens and the coming Playtest lens all import.

Scope, per the SB-060 resolution:
1. Split render from mount. preview.ts's detailPanel / showFact / showDocument / showHypothesis / showQuestion / fallbackJson return `{title, html}` instead of writing host.innerHTML and titleEl.textContent. Each lens owns its own mount.
2. Move unlock.ts and script-editor/doc-preview.ts into the shared module verbatim. Both are already pure.
3. Move the NodeKind union out of canvas/graph.ts into the shared module; graph.ts imports it.
4. Share wireDocFrame with the scale policy as an argument (rail vs full), and put the lightbox in its own module. The rail's `scale = min(1, wrap.clientWidth / width)` must not be baked in.
5. Re-scope the CSS from `#preview .x` to a class, lift the shared `:root` tokens (all 27 common tokens already agree), and reconcile the 4 drifted rules: funn-quote font-size 19 vs 21px, node-card padding, node-json margin-top, .empty padding.
6. Delete the third copy: script-editor/main.ts renderFactCard / renderDocPreview / wireDocFrame / openLightbox now import the shared module. Keep the script lens's own extras (funn-meta, fc-rel, chips, feeds-head) at its call site.
7. One escape helper, not four (kinds.ts escapeHtml, preview.ts esc, jump.ts esc, script-editor/main.ts esc).

## Done when
Both existing lenses look and behave exactly as they do now, the shared renderers have unit tests (they return strings, so they are testable for the first time), and the suite is green.

## Why it blocks
SB-061 builds six new player surfaces. Building them against the canvas-scoped code would fork the render path a third time instead of paying the duplication off once.
