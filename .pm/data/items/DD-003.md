Ruling (Terje, 2026-08-06, SB-026 probe review): the Canvas view is not a supporting overview — it is the main editor, the dialog tree editor the mockup project was named for. Authors must edit all content, check every detail, follow connections, and make new ones on the canvas. This overrides the turn-5 'script-first studio' consolidation and the SB-025 closing note ('views are generated') insofar as they demoted Canvas to a read-only projection.

What stays: content/cases/*.case.md remains the single source of truth. Every canvas edit compiles to a markup patch + recompile (the same write-back channel the script editor uses). The canvas is the main interface, never a second format. Content stays git-diffable; the 0.2 compiler contract holds.

Trade-off accepted: canvas editing requires a markup patch layer (block spans → field-level text patches), sticky layout under edits, and weave content reachable from the canvas. A read-only graph would have been cheaper — and useless (the probe proved it).
