Found during the SB-055 play session (2026-08-09). Terje's browser held a DRAFT_KEY buffer stashed before the SB-054 cull sweep. On boot, both probe editors restore any draft that differs from the ?raw initialText, so the pre-cull buffer silently became the live document, and one play-session save wrote 61 resurrected culled-field lines back to disk. The provenance test caught it; repair was manual (revert + keep the one genuine Summary edit + regenerate).

The fix: stash the base text (or a hash of it) alongside the draft. On boot, three cases: (1) base matches the current file → restore the draft as today; (2) base differs → do NOT silently restore; surface a choice (keep draft / discard draft / show diff) in the status bar or a modal; (3) no base recorded (legacy draft) → treat as (2). Both prototypes/canvas/main.ts and prototypes/script-editor/main.ts share DRAFT_KEY — one guard, two mount points.

Why it matters: every future content migration is one stale browser tab away from a quiet revert. The SB-025 rule (a reload must never wipe unsaved work) stays honored — the guard asks instead of choosing.
