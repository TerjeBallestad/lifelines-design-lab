The playable question: with both lenses live over one file, does authoring actually FLOW — write a passage or a block in the script pane, see it land on the canvas, wire it with a drag, jump back to the text — or does one lens keep interrupting the other (focus steals, surprise scrolls, re-centers while typing)?

How to start: npm run dev → open /prototypes/canvas/ (the 'Editor' tab — script pane | canvas | inspector; the topbar 'script pane' button collapses it).

What to try:
- Write a new fact under a document in the script pane (## f_x + Label/Summary), watch it appear on the canvas without the board reshuffling.
- Name a new block by typing its heading — the SB-040 'create by naming' beat.
- Click canvas nodes and follow the script pane's jump. Move the cursor between blocks and watch the canvas follow. Does the 80ms/block-level pacing feel right, or does it twitch?
- Drag-wire on the canvas (incl. drop-on-empty create from SB-042), then check the markup the gesture wrote reads like something you would have typed.
- ⌘S from the script pane, edit from the inspector — do the two save rhythms (explicit vs auto) ever surprise you?

Answer feeds: SB-037 weave surfacing, the select-to-lift build (SB-040 ruling 3), and whether the script pane needs the outline/preview rails from the standalone page.

Known rough edge (from the build): if you type in the script pane and commit a canvas edit inside the same 150ms window, the canvas patch can overwrite the in-flight keystrokes — call it out if you ever feel it.
