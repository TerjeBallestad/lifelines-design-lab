      Research findings, 2026-08-13. Three parallel web agents: The Sims (all generations), RimWorld lord system (decompiled source + modding docs), and a survey (FFXV, Versu, Hitman, Dwarf Fortress, STALKER, Shadows of Doubt, AC Unity, L4D). Structured around SB-098 Q2's four sub-problems.

      ## The headline for Q2

      Terje's authoring model ("Frank: go to Elling, when there say this") is validated as the authoring SURFACE, but shipped games do not execute it as literal per-character command queues. The convergent runtime model is: **the scene is a small state machine; each state publishes one declarative duty per character; the character's own priority stack decides when to obey.** Two families:

      - **The Sims family (queue-shaped):** one queue per sim, one priority axis. Directed content and autonomy share the SAME queue — autonomy is just what fills the queue when it drains. Scripted events (weddings, parties) are invisible controller objects that PUSH interactions into sims' queues, never seize control.
      - **The RimWorld family (duty-shaped):** the scene (LordJob) is an FSM of states (LordToils); each state assigns each pawn a duty (a data blob: duty def + focus target + position). The pawn's think tree has authored priority rungs — downed/mental break/drafted/starvation outrank duties, ordinary hunger does not. Release = null the duty; no state restore needed because the scene only ever contributed one input.

      FFXV smart locations and Versu practices are a third confirmation: the scene layer speaks in roles + shared facts (blackboard) or affordance suggestions; the agent's normal action system stays the executor. Nobody puppets.

      ## Sync points (our grete_hold_door / tea_hold problem)

      - **Reify the rendezvous.** Sims 1 makes the conversation an invisible object both sims' threads enter. Sims 3 uses "jigs" (invisible objects with routing slots both sims route to). Sims 4 intersects the two interactions' spatial constraints. Lesson: a meeting point is an entity with named seats, not a flag on a step.
      - **RimWorld: state polls a group condition on an interval, then fires a named memo consumed by a transition.** Wedding gate is literally `ticksInToil >= 5000 && bothFiancesInArea`. Rituals author this in XML: `StageEndTrigger_RolesArrived` (wait until named roles have arrived at assigned positions), `_DurationPercentage`, `_PawnDead`.
      - Waiting is a polled "continue next tick" script state (Sims) or a wander-in-place fallback (RimWorld) — never a blocking lock. Every hold we hand-compiled is one of these, expressed as engine structure instead of authored steps.

      ## Failure / unreachable

      - **Author failure as edges, not error handling.** Every RimWorld scene ships call-off transitions (key actor lost, timeout, danger), an auto-injected flee state, and pause/resume twin states. Rituals separate endTriggers from failTriggers per stage — including `StageFailTrigger_TargetPawnUnreachable`, an explicit reachability check with a grace period. Interrupted rituals score pro-rata, not void.
      - **The Sims: failure = the interaction returns false, drops from the queue, and the sim visibly performs the failure** (route-fail stomp). Sims 2 deliberately lets sims attempt doomed routes so they don't look precognitive. No teleport fallbacks anywhere.
      - **FFXV: explicit start/abort contracts** — min cast not met, scene does not start; actor leaves mid-run, scene terminates; every rule has an OnError fact list. The scene bends or dies; it never forces compliance.

      ## Autonomy yield

      - One priority axis per character resolves the whole yield question structurally. Sims 4 names three queue tiers: High (directed), Low (autonomous), Idle (a finished interaction lingers — the sim keeps sitting until something needs the seat). RimWorld duties sit at a fixed think-tree rung and opt in to need satisfaction ("eat, but stay within 16 cells of the flag"). Social scenes are voluntary: guests leave the moment their own AI issues a job; only role-critical cast is hard-required.
      - Sims 4 situations direct by SHRINKING the autonomy space (role state = buff + affordance filter + area anchor), not by scripting every beat. Fewer authored failure paths.

      ## Premise correction

      Shadows of Doubt is a counter-example, not a case: murders are an injected killer GOAL over full autonomy, with layered discovery failsafes (the body eventually smells). It authors premise, not choreography. Dwarf Fortress likewise: locations recruit whoever is present, roles emerge, missing instruments are improvised — the fully emergent end, no scene control at all.

      ## What this hands SB-098 Q2

      1. The serial global step queue is confirmed as the root smell. No shipped game runs multi-character scenes through a serial pipe. Both proven shapes are per-character (queue or duty) with the scene as a separate coordinating layer.
      2. The rewrite choice is not "command queues: yes/no" but **which family**: Sims-style pushed interactions into per-character queues, or RimWorld-style stage/role/duty FSM. For authored narrative visits with named cast, the RimWorld ritual schema (roles, ordered stages, per-stage per-role duty + endTriggers + failTriggers) is the proven pure-data authoring format — it maps almost 1:1 onto Terje's sentence: stages are the "then" boundaries, roles are Frank/Grete/Elling, RolesArrived is the meeting point.
      3. The three band-aids each have a named engine-level replacement: grete_hold_door / tea_hold → per-stage duties + RolesArrived-style end trigger; await_answer → stage boundary (endTrigger on the answer event); no_wait → the duty model makes it free, since characters act in parallel by default and sync only at stage edges.
      4. Failure handling must enter the grammar with the rewrite: per-stage fail triggers with a grace period, and a call-off path. Prior art says this is not optional polish — every system that skipped it (STALKER) pinned its story NPCs instead.
